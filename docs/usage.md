# Docker Manager 使用手册

面向「会用 `docker` 命令、但刚打开这个面板」的人。全文按「我想干什么」组织，所有按钮名、提示语、禁用条件都取自当前源码。

---

## 1. 这是什么

Docker Manager 是一个**跑在浏览器里的本机 Docker 管理面板**：容器、镜像、网络、数据卷都在页面上操作，能看实时日志、进容器终端、跟容器双向传文件。

三条必须先知道的事实：

- **管理的是宿主机的 Docker**。后端把宿主机的 `/var/run/docker.sock` 挂进容器（`deploy/docker-compose.yml:7`），所以页面上删的东西就是 `docker rm` 删的东西，没有隔离层。
- **没有登录、没有用户、没有权限分级**。谁能打开这个页面，就等于拿到宿主机 root 等价权限。
- **单机、只绑本机**。默认只在 `127.0.0.1:8088` 上监听，管不了别的机器上的 Docker。

**它不做的**：不做多节点、不做编排（没有 Compose/K8s 概念）、不做镜像构建（没有 Dockerfile 上传/构建）、不做用户与审计、不落任何自己的数据（没有数据库，页面上的东西全部实时来自 Docker）。

---

## 2. 启动与打开

1. 确认当前用户能访问 `docker.sock`（Linux 上在 `docker` 组内），然后：

   ```bash
   cd docker-manager/deploy
   docker compose up -d --build
   ```

2. 等两个容器都 `Up`（`docker compose ps`）。首次构建要拉基础镜像并编译前端，**2–10 分钟**，命令看起来「卡住」是正常的。
3. 浏览器打开 **http://127.0.0.1:8088**。

**首次打开你会看到**：左侧深色侧边栏，顶部是 🐳 Docker Manager / 容器管理平台，下方四个导航项「容器 / 镜像 / 网络 / 卷」，侧边栏底部写着 `v1 · 本地部署 · 127.0.0.1`；右侧顶部有当前页标题和一行说明，右上角是一个健康状态点（`服务正常` / `服务异常` / `检测中…`，每 15 秒自动探一次 `/api/health`）和「刷新」按钮；默认落在「容器」页。

**改端口 / 允许局域网访问**（各改一行，改完 `docker compose up -d`，不用重新构建）：

- 换端口：`deploy/docker-compose.yml` 里 `"127.0.0.1:8088:80"` → `"127.0.0.1:9090:80"`。
- 允许局域网：改成 `"0.0.0.0:8088:80"`——**危险**，做之前先读 `deployment.md` 第 5 节「安全」；推荐用 SSH 隧道 `ssh -L 8088:127.0.0.1:8088 user@server`。

细节与其余配置见 `docs/deployment.md` 第 4 节。

## 3. 界面总览

侧边栏是**四个页面**（`/containers`、`/images`、`/networks`、`/volumes`），根路径 `/` 直接重定向到容器页；页面之间靠左侧导航切换，没有面包屑、没有二级路由。「容器」页之上再叠**四层子界面**（日志抽屉、终端抽屉、文件拷贝抽屉、打包镜像弹窗）和**新建容器弹窗**。

| 入口 | 管什么 | 页面标题下的一行说明 |
|------|--------|----------------------|
| 容器 | 列表、启停、重启、暂停/恢复、删除、看日志、进终端、传文件、打包镜像、新建容器 | 启动、停止、查看日志、进入终端、拷贝文件、打包镜像 |
| 镜像 | 列表、拉取、从镜像运行容器、导出 tar、删除 | 拉取、删除镜像，导出为 tar 文件 |
| 网络 | 列表、创建、删除 | 查看与创建 Docker 网络 |
| 卷 | 列表、创建、删除、复制挂载点路径 | 查看与创建数据卷 |

**互相跳转的真实情况**：

- 从「镜像」页某行的「运行」按钮，会**在本页弹出新建容器向导**（镜像名已预填），创建完成后**仍停留在镜像页**，只是刷新了镜像列表——**不会自动跳到容器页**，新容器要自己去「容器」页看。
- 从「容器」页的「新建容器」也会弹出同一个向导，但镜像框是**空的**，需要自己填或点常用镜像按钮。
- 页面顶部的「刷新」会重建当前页面组件并重新取数；它是**整页重挂载**，正在看的日志/终端抽屉会被一起关掉。
- 没有一个页面能跳到另一个页面的具体某一行，也没有「详情页」互相跳转。

## 4. 五分钟上手（一步步来）

| 步骤 | 点哪里 | 会看到什么 | 失败时先看什么 |
|------|--------|------------|----------------|
| 1. 拉一个镜像 | 「镜像」页 → 左上输入框填 `nginx:alpine` → 点「拉取」（或直接回车） | 按钮转圈，成功后右上角提示 `已拉取 nginx:alpine`；Docker Hub 不可达时会提示 `已拉取 nginx:alpine（经镜像源 docker.m.daocloud.io）` | 一直转圈看排障手册「拉取镜像失败 / 一直转圈」；正好 60 秒报 504 看「拉取大镜像时页面报 504」 |
| 2. 从镜像运行容器 | 「镜像」页 → 该行「运行」→ 向导里点「Nginx」预设（自动填好镜像/容器名 `nginx-web`/端口 `8080:80`）→ 右下角「创建并启动」 | 弹窗关闭，镜像列表刷新；提示 `容器「nginx-web」已创建` | 报 404`镜像「…」不存在`＝这台机器上还没有这个镜像；报 409 ＝ 端口或容器名被占用 |
| 3. 看日志 | 「容器」页 → `nginx-web` 行的 `⋯` 菜单 → 「查看日志」 | 右侧滑出深色日志抽屉，标题 `容器日志 · nginx-web`，状态点是绿的、写着 `实时` | 抽屉里出现红色告警「无法获取日志」或黄色「日志流已结束」，按提示点「重连」 |
| 4. 进终端敲命令 | 关闭日志抽屉 → 同一行 `⋯` → 「进入终端」 | 抽屉标题 `交互终端 · nginx-web`，状态 `已连接`，右上角显示 `列 × 行` 尺寸 | 「进入终端」是灰的：只有 `running` 状态的容器能进；提示会直接写在菜单项后面 |
| 5. 把文件拷进去再拷出来 | 终端抽屉里敲 `echo hello > /tmp/hi.txt` 回车；关闭抽屉 → `⋯` → 「文件拷贝」→ 拖入本地任意文件、目标路径填 `/tmp` → 「开始拷贝」；再把「容器内路径」填 `/tmp/hi.txt` → 「下载」 | 上传成功提示 `已拷入 /tmp`；下载提示 `已开始下载`，浏览器下载到一个 `container-file.tar` | 上传报 413 看「上传稍大的文件报 413」；下载报 `path does not exist` 检查路径拼写 |
| 6. 停掉并删除 | 关闭抽屉 → 行内「停止」（先点「重启」旁边那个）→ 确认状态变成 `exited` → `⋯` → 「删除容器」→ 弹窗点「删除」 | 提示 `nginx-web 已停止`、`已删除` | 删除不弹错误就说明成功了；列表里那一行会消失 |

> 第 5 步里拷出来的永远是 **tar 包**，不是一个裸文件——即使你只拷一个文件。

## 5. 常见任务

### 5.1 我想看某个容器的日志

1. 「容器」页 → 目标行 `⋯` → **查看日志**。
2. 抽屉工具栏左侧两个下拉：
   - **stream**：`stdout` / `stderr` / `全部`（`全部` = 两者都要）。
   - **tail**：`最近 100 行` / `最近 500 行` / `最近 2000 行`。切换任一项都会**断开重连**（重新拉一遍历史）。
3. 工具栏右侧按钮：**暂停/继续**（暂停后停止往视图里写，但连接还在）、**清屏**（清空视图与截断计数）、**下载**（把当前视图里的行存成 `容器名.log`）、**重连**（重置退避、清屏后重连）、**断开**（手动断开，且**不再自动重连**，直到你点「重连」）。
4. 状态区显示 `实时` / `连接中` / `已断开` / `已断开 · Ns 后重连` / `已断开（手动）`，后面跟当前 `N 行`，被丢过行时再跟一段 `· 已截断 N 行`。
5. **只要最近 N 行**：选 tail 下拉即可。**只看 stderr**：stream 选 `stderr`。**想一直跟着**：不用操作，默认就是实时跟随；往上滚会停止自动跟随，滚回底部自动恢复。

### 5.2 我要进容器里敲命令

- **入口**：容器行 `⋯` → 进入终端。**只有状态是 `running` 的容器能进**：
  - 容器是 `paused` → 菜单项灰掉，后面写着「（容器已暂停，请先恢复）」。
  - 容器是 `exited`/`created` 等未运行状态 → 灰掉，写着「（容器未运行，请先启动）」。
  - 原因：进入终端走的是 `docker exec`，需要**活着的进程**；对已暂停（冻结）的容器执行 `exec_create` 会被守护进程一直挂住，抽屉只会永远停在「连接中…」。
- **Ctrl+C**：有选中文本时＝**复制**（并且不会再往容器发 `\x03`，不会打断你的命令）；没选中时＝正常的 SIGINT 中断。`Ctrl+Shift+C` 同样按「有选中就复制」处理，没选中时什么都不发。
- **粘贴**：`Ctrl+V` 或**鼠标右键**（右键已接管为粘贴）。浏览器若不允许读剪贴板，会提示「浏览器未允许读取剪贴板，请在地址栏放开权限后重试」。
- **窗口大小**：终端就绪后会把行列数发给后端（右上角能看到 `列 × 行`），拖动浏览器窗口会自动重算；容器里 `stty size` 应该和它一致。抽屉动画没结束时尺寸为 0，代码会跳过这次适配，动画结束后自动补上。
- **断线**：会自动重连，延迟从 1 秒开始翻倍，最长 30 秒（状态区显示 `连接已断开 · Ns 后重连`）。关闭码 1000（正常结束）和 1008（被同源守卫拒绝）**不会**自动重连。
- **容器重启/退出后**：会话结束会显示 `[会话已结束]` 和告警「会话已结束」，此时只会提示你点「重连」开一个**新会话**——不会悄悄替你新建。抽屉是关闭即销毁的，所以关掉终端抽屉就等于断开连接，重新打开才是新连接。
- **进不去**：容器里没有 `/bin/sh`（distroless 类镜像）时无法进入。终端固定用 `/bin/sh`，界面上没有改 shell 的地方。

### 5.3 我要把本地文件放进容器 / 从容器取文件

「文件拷贝」抽屉分上下两段：

**拷进去（本机 → 容器）**

1. 拖拽文件到虚线框，或点「点击选择」。**一次只能一个文件**（再选会替换掉上一个）。
2. 「容器内目标路径」默认填 `/tmp`，要填**容器内已存在的目录**（后端把它打包成 tar 后 `put_archive` 到这个目录，目录不存在会报错）。
3. 点「开始拷贝」→ 提示 `已拷入 <目标路径>`。文件名保持你本地的文件名。

**拷出来（容器 → 本机）**

1. 「容器内路径」默认填 `/`，可填文件也可以填目录，例如 `/app/logs`。
2. 点「下载」→ 提示 `已开始下载`，浏览器拿到的是一个 tar（文件名固定为 `container-file.tar`）。
3. **总是 tar**：目录是一棵目录树打成一个 tar，单个文件也会被包在 tar 里。要拿裸文件就在本机解开：`tar xf container-file.tar`。
4. 路径写容器内的**绝对路径**；路径不存在或容器已删，会弹出「下载失败」并显示后端原因（不会假装成功）。

### 5.4 我要用面板跑一个新容器

入口：容器页右上「新建容器」，或镜像页某行的「运行」（会带上该镜像名）。

1. **镜像**（必填）：本地已有的镜像名，例如 `mysql:latest`。面板**不会替你拉取**；本地没有就直接报 `镜像「…」不存在，请先到镜像页拉取。`
2. **容器名**：选填。留空由 Docker 自动生成。
3. **端口映射**：一行一个，格式 `[IP:]宿主机端口:容器端口[/协议]`。`8080:80`、`127.0.0.1:8080:80`（只绑本机）、`53:53/udp`、光写 `80`（让 Docker 随机分配宿主机端口）。端口这一项额外允许用逗号分隔。端口必须是 1–65535 的数字。
4. **环境变量**：一行一个 `KEY=VALUE`；变量名只能字母/数字/下划线且不能以数字开头。值里可以带 `=`。
5. **目录挂载**：一行一个 `宿主机路径:容器路径[:ro]`；左边也可以写**数据卷名**（`mysql-data:/var/lib/mysql`），容器路径必须是绝对路径。第三段只认 `ro`/`rw`。
6. **启动命令**：选填，留空用镜像自带命令；填了就整体覆盖（例如 `sleep infinity`）。
7. **重启策略**：下拉四选一，可清空＝不自动重启。选项文案：`always（总是重启，推荐）`、`unless-stopped（手动停止后不重启）`、`on-failure（异常退出才重启）`、`no（从不重启）`。
8. **立即启动**（开关，默认开）：开 → 按钮写「创建并启动」；关 → 只创建，按钮写「仅创建」，之后到容器页手动「启动」。
9. 上方一排**常用镜像**按钮是给不想记格式的人用的：点 MySQL / Redis / Nginx / PostgreSQL / Ubuntu（只创建，用来练手）会自动填满整张表，点「清空」复原。MySQL 与 PostgreSQL 会**随机生成一个密码**并在创建成功后的弹窗里显示一次——**关掉就再也看不到**（面板没有查看已设密码的功能，只能进容器重置）。

**常见报错怎么读**（都是中文，直接看提示即可）：

| 提示 | 含义 |
|------|------|
| `镜像「x」不存在，请先到镜像页拉取。` | 本地没有这个镜像 |
| `端口已被占用：…` | 宿主机端口被别的进程/容器占了 |
| `容器名已被占用：…` | 已有同名容器（含已停止的） |
| `端口必须是数字：…` / `端口超出范围 (1-65535)：…` | 端口写法不对 |
| `端口映射格式应为 宿主机端口:容器端口：…` | 冒号段数不对（多于三段） |
| `环境变量需要 KEY=VALUE 格式：…` / `环境变量名不合法…` | 环境变量写法不对 |
| `挂载格式应为 宿主机路径:容器路径[:ro]：…` / `容器内路径必须是绝对路径：…` | 挂载写法不对 |
| `请填写镜像名，或点上方常用镜像按钮自动填好` | 镜像框为空就点了创建 |

### 5.5 我要把容器的当前状态打包成镜像、把镜像导出成 tar

**打包为镜像（commit）**：容器行 `⋯` → 「打包为镜像」→ 填「仓库名」（打开时已根据容器名预填一个合法名字，非法字符会被去掉）和「标签」（默认 `latest`）→ 点「打包」→ 提示 `已打包为 仓库名:标签`。仓库名留空会提示「请填写仓库名」。它对容器当前的文件系统状态做快照，**不停止容器**；容器越大等得越久（一次提交最长等 300 秒，超时会报错，但后端可能还在做）。

**导出镜像为 tar**：镜像页该行「导出」→ 浏览器下载一个 tar，文件名由第一个标签生成（`mysql:latest` → `mysql_latest.tar`）。成功后提示 `已开始导出`。导出会先做一次「预检」，**预检超过 30 秒没拿到响应就会取消并报错**（提示里让你确认后端与 Docker 守护进程），随后真正的传输交给浏览器下载管理器；几十 GB 的镜像也能导，因为它不在服务器落盘。

### 5.6 我要建数据卷 / 网络，以及为什么删不掉

- **建卷**：卷页 → 「创建卷」→ 填名称（例如 `app-data`）→ 「创建」→ 提示 `已创建卷 app-data`。名称留空提示「请输入卷名称」。
- **建网络**：网络页 → 「创建网络」→ 填名称（例如 `my-net`）、选驱动（`bridge（默认）` / `overlay` / `macvlan`）→ 「创建」→ 提示 `已创建网络 my-net`。名称留空提示「请输入网络名称」。
- **删不掉的原因**：
  - 网络/卷**被容器占用**时，Docker 拒绝删除，页面会弹红条把守护进程的原话显示出来（面板不会替你强制断开容器）。
  - `bridge` / `host` / `none` 是 Docker 内置网络，**删除按钮直接是灰的**，鼠标悬停提示「Docker 内置网络不可删除」。
  - 删除卷的确认框明确写着「卷中数据将一并丢失」——这里没有回收站。
- 面板创建容器时，挂载里写的数据卷名会出现在卷页（Docker 会自动建）。

### 5.7 一键启停 / 重启 / 暂停 / 恢复 / 删除

全部在容器页行内：

| 按钮 | 什么时候可点 | 结果提示 |
|------|--------------|----------|
| 启动 | 状态不是 `running`，且该行没有操作在跑 | `<容器名> 已启动` |
| 停止 | 状态是 `running`，且该行没有操作在跑 | `<容器名> 已停止` |
| 暂停 / 恢复 | `running` 时显示「暂停」，`paused` 时显示「恢复」（同一个位置互换） | `<容器名> 已暂停` / `已恢复` |
| 重启 | 只要该行没有操作在跑就能点（未运行的容器也能点，Docker 会把它启动起来） | `<容器名> 已重启` |
| 删除容器（在 `⋯` 菜单里） | 任何状态 | 确认后提示 `已删除` |

- 一次操作进行中时，该行所有按钮都会临时禁用，避免连点导致守护进程报错；被点的那一个按钮会转圈。
- **删除的语义是「强删」**：面板调删除接口时固定带 `force`，界面上没有开关、确认框里也没写。所以**运行中的容器可以直接删掉**（会被杀掉并移除），不需要先「停止」。菜单里最后一个「删除容器」是分隔线之后的项，确认框文案是「确认删除容器「名称」？此操作不可撤销。」，按钮是「删除 / 取消」。
- 镜像页的「删除」同样是**强删**（被容器引用的镜像也会被删掉，之后那些容器就成了悬空引用），确认框只写「确认删除镜像「标签」？」。删镜像前想清楚。

## 6. 每个页面逐项说明

### 6.1 全局外壳（所有页面共用）

| 元素 | 说明 |
|------|------|
| 左侧导航 | 容器 / 镜像 / 网络 / 卷 四项；当前项高亮（按路径前缀匹配） |
| 页面标题 + 说明 | 来自路由元信息，见第 3 节表格 |
| 健康状态点 | 绿点 `服务正常`、红点 `服务异常`、灰点 `检测中…`；进入页面即探一次，之后每 15 秒探一次 |

**错误提示怎么呈现**：短错误（不超过 140 字且不含换行）用右上角红色 toast；长错误或多行错误（比如拉取失败时会列出每个镜像源的原始报错）改用**弹窗**，标题是操作名（如「操作失败」「创建容器失败」「下载失败」），按钮「知道了」。全站请求默认 **30 秒超时**；只有三类请求例外：拉取镜像**不限时**，创建容器和打包镜像各放宽到 **300 秒**。

### 6.5 日志抽屉

标题 `容器日志 · <容器名>`，占屏宽 62%，关闭即断开。工具栏见 5.1。日志区等宽字体、深色背景、自动滚到底（手动上滚即暂停跟随）。

状态与提示文案：

| 情况 | 你会看到 |
|------|----------|
| 正在连 | `连接中`，空区显示「等待日志输出…」 |
| 连上 | 绿点 + `实时 · N 行` |
| 容器不存在/已删 | 红色告警「无法获取日志」，说明里会补一句「容器可能已被删除或改名，请刷新列表后重试。」 |
| 容器已停止、流结束 | 黄色告警「日志流已结束」：容器可能已停止或退出，可点「重连」重新读取 |
| 传输断掉 | 红色告警「连接已断开」，自动重连；重连前会在日志里插一行 `... 连接已断开，正在重连（可能重复最近若干行）...` |
| 服务端拒绝（关闭码 1000/1008） | 红色告警「连接已关闭」，写明关闭码，不会自动重连 |

**缓冲区上限（会发生丢行，如实说明）**：后端每 100 毫秒把日志合并成一帧，待发缓冲最多 2000 行，超出**丢最旧**并给出上面那句英文提示；前端两帧之间最多缓存 5000 行（超出丢最旧并插入中文提示），视图里最多保留 3000 行，更老的会被静默移除（计数在工具栏）。

### 6.6 终端抽屉

标题 `交互终端 · <容器名>`，占屏宽 72%，关闭即断开。工具栏左侧是状态点 + 状态文字（`连接中…` / `已连接` / `会话已结束` / `已断开（手动）` / `连接已断开 · Ns 后重连`）和当前 `列 × 行`；右侧是提示语「选中文本 Ctrl+C 复制 · Ctrl+V / 右键 粘贴」加三个按钮：**重连**（清屏并开新会话）、**断开**（停止且不再自动重连）、**清屏**（只清屏幕，不断连接）。

提示情况：

| 情况 | 你会看到 |
|------|----------|
| 容器不存在 | 红色告警「无法打开终端」+ 后端原因（含「容器可能已被删除或改名」提示） |

| 复制成功 | 短暂提示「已复制」；都失败时提示「复制失败，请手动选中后使用浏览器复制」 |

终端滚动回溯保留 5000 行。**入口禁用条件见 5.2**（只有 `running` 可用，原因也写在菜单项后面）。

## 7. 注意事项与已知限制

**安全（最重要）**

- **没有登录**：任何能打开这个页面的人都能完全控制宿主机 Docker，等价于宿主机 root。默认只绑 `127.0.0.1`，因此**只能本机访问**。
- 远程访问请用 **SSH 隧道**：`ssh -L 8088:127.0.0.1:8088 user@server`；或者用**自带认证**的反向代理。细节见 `docs/deployment.md` 第 5 节。**不要**直接把端口暴露到公网。
- 自己加前置反代时，若**改写了 Host 头**（例如固定成 `backend:8088` 或自己的域名），所有写操作（POST/PUT/PATCH/DELETE）会返回 **403**「cross-site request rejected (Origin not allowed)」，终端与日志的 WebSocket 会被拒并**以关闭码 1008 结束**。反代必须保留原始 Host（nginx 用 `proxy_set_header Host $http_host;`，Apache 用 `ProxyPreserveHost On`）。详见 `docs/troubleshooting.md` 的「写操作全报 403」。
- 这条同源守卫**是防跨站写操作，不是身份认证**，替代不了访问控制。

**功能上的已知限制（如实）**

- **TTY 容器的日志会一字符一行**：用 `docker run -t` 创建（或镜像自带 `Tty: true`）的容器，它的日志流不是按行分帧的，面板按「一个数据块＝一行」渲染，于是 `hello` 变成 `h`/`e`/`l`/`l`/`o`。**从本面板创建的容器不设 TTY，不受影响**；终端功能也不受影响。要看正常日志请重建容器时去掉 `-t`，或直接在命令行 `docker logs` 看。
- **导出大镜像、拉取大镜像会长时间等待**，这是正常的（进度条之类的东西面板不提供）。导出前有一次 30 秒的预检，超时会取消并报错；预检只校验响应状态，**如果守护进程在返回 200 之后才出错**（打包大层时 I/O 错误、磁盘满），你仍可能拿到一个被截断的 tar，而界面已经说了「已开始导出」。
- **日志会丢最旧的行**：客户端跟不上时按 5.1 末尾的规则丢弃并给出提示，不是全量。
- **终端与日志都是直连容器的**：抽屉一关就断开；容器重启/退出后需要重新打开（终端会提示「会话已结束」，点「重连」开新会话）。传输断开会自动重连（1 秒起指数退避到 30 秒），但关闭码 1000/1008 不重连。
- **重连会重放历史**：日志重连时会重新按当前 tail 拉一遍，可能重复显示最近若干行，视图里会插一行提示标出重复段的起点。
- **日志按容器名前缀匹配**：后端取「名字以该名称开头」的第一个容器，且优先匹配运行中的容器。名字互为前缀的容器（如 `web` 与 `web-2`）有取错的风险。
- **面板不做持久化**：没有数据库，所有状态都实时来自 Docker，重启面板不丢任何东西；反过来，面板里也不会记住任何偏好（搜索词、tail 选择、展开状态都不保存）。
- **一键删除是强删**：容器删除与镜像删除都固定带 `force`，界面没有开关。
- **文件上传吃内存**：拷入会把整个文件读进内存再打成 tar；超大文件（GB 级）建议直接用 `docker cp`。
- **没有镜像构建、没有详情页、没有终端 shell 选择**：终端固定 `/bin/sh`，容器里没有它就进不去。
- **网络/卷被占用时删不掉**，面板不会替你强制解除占用。
- **健康检查只证明后端活着**：`服务正常` 只代表 `/api/health` 返回了 `ok`，不代表 Docker 守护进程可用。

## 8. 出问题了先看哪里

| 现象 | 先查什么 | 去哪儿 |
|------|----------|--------|
| 拉取镜像失败 / 一直转圈 | `docker pull` 是否也超时；镜像源配置 | 排障手册「拉取镜像失败 / 一直转圈」 |
| 拉取大镜像时页面报 504（正好 60 秒） | nginx 的 `proxy_read_timeout` 是否还是 3600s | 排障手册「拉取大镜像时页面报 504」 |
| 导出镜像时中断 / 转圈不动 | 长连接是否被前置代理掐断；后端是否流式 | 排障手册「导出镜像时中断 / 转圈不动」 |
| 上传稍大的文件报 413 | nginx `client_max_body_size` | 排障手册「上传稍大的文件报 413」 |
| 拷贝目录失败 | 目标路径是否存在、是否以 `/` 结尾；镜像里有没有 `tar` | 排障手册「拷贝目录失败」 |
| 页面报 500，日志里 `No such image: sha256:...` | 是不是容器引用的镜像被删了（悬空引用） | 排障手册「页面报 500，日志里 `No such image: sha256:...`」 |
| 端口列显示成断开的片段（`127.0.0.1:17474-` / `>7474/tcp`） | 属于历史缺陷，确认前端是否为最新版本 | 排障手册「端口列显示成断开的片段」 |
| 终端显示乱码 / 排版错乱 | 容器里 `stty size` 与终端右上角尺寸是否一致 | 排障手册「终端显示乱码 / 排版错乱 / 看不清」 |
| Ctrl+C 复制不了 / Ctrl+V 粘贴不了 | 是否用的是最新前端；剪贴板权限 | 排障手册「Ctrl+C 复制不了、Ctrl+V 粘贴不了」 |
| 终端连不上 / 输入没反应 | 容器里有 `/bin/sh` 吗、容器是 running 吗、`/ws/` 升级头、`stdin=True` | 排障手册「终端连不上 / 输入没反应」 |
| 日志页面卡住 / 整个服务无响应 | 是否在单个事件循环里做阻塞读 | 排障手册「日志页面卡住 / 整个服务无响应」 |
| 日志里每个字符各占一行 | 容器是不是 TTY 创建的（`-t`） | 排障手册「日志里每个字符各占一行」 |
| `docker compose up --build` 看起来卡住 | 另开终端 `docker compose logs -f frontend` | 排障手册「`docker compose up --build` 看起来卡住」 |
| 构建时拉基础镜像失败 | 守护进程能否访问 Docker Hub / PyPI | 排障手册「构建时拉基础镜像失败」 |
| 前端刷新页面报 404 | nginx 的 SPA history 回退 | 排障手册「前端刷新页面报 404」 |
| 页面能开但所有接口都失败 | nginx 与 backend 是否互通（`expose` 是故意的） | 排障手册「页面能开但所有接口都失败」 |
| 写操作全报 403 / 终端连不上（WS 1008） | 前置反代是否改写了 Host | 排障手册「写操作全报 403 / 终端连不上」；安全说明见 `deployment.md` 第 5 节 |
| 登录/刷新后跳到 80 端口，或子路径 404 | 反代用的是 `$host` 还是 `$http_host` | 排障手册「登录/刷新后跳到 80 端口，或子路径打开是 404」 |
| `Permission denied` 访问 docker.sock | 当前用户是否在 `docker` 组 | 排障手册「`Permission denied` 访问 docker.sock」 |
| 改了 `ports` 后局域网还是访问不了 | 防火墙与绑定地址 | 排障手册「改了 `ports` 后局域网还是访问不了」 |

页面本身的通用排查顺序：右上角状态点是不是 `服务异常` → 按 F12 看 Network 里失败请求的响应体（后端的中文原因就在 `detail` 字段）→ 再看 `docker compose logs --tail=50 backend`。

| 镜像源 | `IMAGE_MIRRORS` 环境变量（应用级降级），不是 daemon 的 `registry-mirrors` |
| tail / 最近 N 行 | `docker logs --tail=N` |
| stream / stdout / stderr / 全部 | `docker logs` 的 stdout/stderr 过滤 |
| 实时（绿点） | `docker logs -f`（follow） |
| 暂停 / 恢复 | `docker pause` / `docker unpause`（冻结进程，不是停止） |
| 重启 | `docker restart` |
| 删除容器 / 删除镜像 | `docker rm -f` / `docker rmi -f`（面板固定带 force） |
| 打包为镜像 | `docker commit 容器 仓库名:标签` |
| 导出 / tar | `docker save`（本面板导出时保留仓库名与标签） |
| 拷贝（拷入/拷出） | `docker cp`（面板内部按 tar 传输） |
| 端口列 `8088->80/tcp` | `docker ps` 的 `PORTS` 列 |
| expose vs ports | 容器**只声明不映射**的端口在面板里显示成裸形式（`80/tcp`），映射过的才显示 `宿主机端口->容器端口`；这也对应 compose 里后端 `expose`、前端 `ports` 的区别 |
| 未运行 / 已停止 | `exited` / `created` 等非 `running` 状态 |
| 已截断 | 缓冲上限触发，丢弃了最旧的日志行 |

### 10.2 发现的不一致 / UI 可疑之处

1. **「从镜像页运行会跳到容器页」不成立**（任务书假设与源码不符）：镜像页的向导 `@created` 只调用本页的 `load()` 刷新镜像列表，不会跳转到容器页（`ImagesView.vue:89`）。真实行为已按实际写在第 3 节。
2. **没有「容器详情」界面**：`scope.md:24`、`spec.md:83` 都写了容器「列表/详情」，但前端没有任何详情入口，`GET /api/containers/{cid}` 无前端调用（`api/index.ts:71-82` 未暴露 detail 方法）。第 6.3 节照实写成「没有详情页」。
3. **日志 tail 默认值不在选项里**：`ContainerLogs.vue:81` 默认 `tail=200`，但下拉只有 `100 / 500 / 2000`（`:11-13`）。首次打开时选择框会显示裸值 `200`，一旦切走就再也切不回 200。
4. **`development.md` §3 的约定与代码不符**：「后端错误统一走 `showApiError(err, title)`，不要各写各的 `ElMessage.error`」（`development.md:83`），但 `ContainersView.vue:271-274`、`NetworksView.vue:122-125`、`VolumesView.vue:97-100`、`FileCopyDrawer.vue:105-108` 都直接 `ElMessage.error`。后果：这些页面**长错误不会弹窗**，只有固定 3 秒的 toast。
5. **`troubleshooting.md` 关于导出的建议已过时**：该文说「检查 `frontend/src/api/index.ts` 里导出用的是不是 `NO_TIMEOUT`（`{ timeout: 0 }`）」（`troubleshooting.md:63-67`），但导出早已不走 axios——`imagesApi.saveUrl`（`api/index.ts:89`）+ `startDownload()` 的 30 秒 fetch 预检 + 裸 `<a href>`（`utils/download.ts:50-104`）。同时 `development.md:84` 说「长耗时请求用 `NO_TIMEOUT`…只有拉取镜像和导出镜像需要」，而实际 `create`/`commit` 用的是 300 秒的 `LONG_OP_TIMEOUT`（`api/index.ts:69-81`）。
6. **`api/index.ts:60-61` 的注释说「a missing image is pulled first」不实**：`containers.py:121-127` 在镜像不存在时直接返回 404，并不自动拉取（`e2e_verify.py:495-518` 也是先挑一个本地已存在的镜像）。手册里按真实行为写「面板不会替你拉取」。
7. **删除的 `force` 无处可看**：容器删除 `remove(row.id, true)`（`ContainersView.vue:393`）、镜像删除 `imagesApi.remove(row.id, true)`（`ImagesView.vue:202`）都固定强删，界面上既没有开关、确认框也没提；`README.md:265` 只说了「镜像删除是强删」，没提容器删除同样是强删。
8. **恢复按钮的可见性依赖 `state === 'paused'`**：`ContainersView.vue:88-109` 用 `v-if/v-else-if` 决定「暂停」还是「恢复」，`restarting`/`removing` 等过渡态既不是 `running` 也不是 `paused`，此时**该位置两个按钮都不显示**（列表刷新后恢复正常）。
9. **`README.md:155` 的 `/ws/logs` 参数表只列了 `stdout/stderr`**，漏了界面上的「全部」（`stream=both`，`ws.py:95-96` 明确支持）。
