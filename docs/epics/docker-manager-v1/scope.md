## 1. 用户故事

（来源：对话定案 + 总体计划 §2，本 Epic 无 feature-plan）

- 作为运维/开发者，我打开浏览器就能查看并操控宿主机上的 Docker 容器（列表、启停、日志），不用敲 docker 命令。
- 作为使用者，我能进入运行中的容器拿到交互式终端，并把文件在主机与容器之间双向拷贝，全在界面完成。
- 作为使用者，我能把容器打包成镜像、把镜像导出 tar 下载，也能管镜像/网络/卷，全程不碰命令行。

## 3. 架构约束

| 约束 | 说明（对本 Epic 为何成立） |
|------|---------------------------|
| 后端 FastAPI (Python 3.12) + docker-py | 熟悉、开发快；对接 Docker Engine API |
| Python 环境用 **uv 虚拟环境** | 统一用 uv 管理依赖与 venv；开发用 `uv venv`，**Dockerfile 内也用 uv 安装**，`pyproject.toml` + `uv.lock` 锁文件（对话定案） |
| 前端 Vue3+Vite+TS+Element Plus | 中后台组件齐全 |
| 后端挂载宿主机 docker.sock 访问 Docker | 单机自用最简；**使后端具宿主机 Docker 完全权限**，仅受信任环境 |
| 日志/终端走 WebSocket | 实时不在界面轮询 |
| 平台自身 Docker 容器化 + docker-compose | 一键拉起 |
| 交互式终端用 xterm.js | 前端模拟终端，docker exec 需 tty=true 与 resize 处理 |
| 文件拷贝后端中转 | 平台容器内，copy 流程经临时目录 + get/put_archive |
| 后端对外端口 **8088** | 对话定案 |
| 所有动作经 Web 界面 | 后端封装 docker 操作为 API，前端统一入口 |

## 4. 数据实体

无持久化业务表——本平台为**无状态管理面板**，实时数据直接来自 Docker Engine API（只读/操作，不落库）。

| 实体 | 存储 | 说明 |
|------|------|------|
| 容器/镜像/网络/卷等 | Docker daemon（消费） | 全部只读自 Docker API，无新增表 |
| 平台自身配置 | 后端配置/环境变量（新） | `config.py`：DOCKER_HOST、上传/导出临时目录、端口 |

> 注：若后续加配置持久化（如多主机地址）才需补充数据模型，v1 无此需求。

## 5. 上下游依赖

| 上游/依赖 | 关系 |
|-----------|------|
| 宿主机 Docker daemon | 必需——平台所有能力的底层依赖（挂 socket/TCP） |
| 无对接外部系统 | 无（独立项目，无既有存量系统） |
| 无被依赖方 | 无（全新项目） |

**Epic 内开发序列**：后端骨架→容器&日志&终端→镜像/网络/卷→前端→联调部署（无外部硬上游依赖）。

## 6. 验收标准（每条标注来源）

> v1 验收闭环见总体计划 §6 阶段 5。

1. `docker compose up` 后平台可从浏览器访问（端口 8088），`/api/health` 正常。
2. 能在页面完成：查看容器 → 看实时日志 → **进入终端执行命令** → **文件拷入/拷出容器** → 容器打包成镜像 → **导出 tar 下载**。（总体计划 §6/§2 验收；完整性自用闭环）
3. F1-F10 各动作均可经界面触发，不依赖命令行。（总体计划 §2 验收要点）
4. 明确不约束的项：登录（不做）、多用户（不做）、监控（P1）、镜像导入（v1.1）——均标注来源 n.notPresent（对话定案）。
